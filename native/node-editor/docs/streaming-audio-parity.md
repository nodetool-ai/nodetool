# F31 streaming audio parity

Scope: native PCM monitoring and replay. Compressed realtime formats remain unsupported. Findings below describe the baseline that the acceptance tests reproduce.

## Evidence and missing behavior

F31-F1. The runtime already supplies PCM. [`chunkSchema`](../../../packages/protocol/src/messages.ts) permits interleaved `Float32Array` in process and base64 strings on the wire. [`websocket-client-session.ts`](../../../packages/websocket/src/websocket-client-session.ts) calls `encodeNativeAudioChunks` before either JSON or MsgPack serialization. Native consumes the base64 wire form, never a fabricated file URL. [`cv.ts`](../../../packages/audio-nodes/src/lib/cv.ts) supplies `encoding`, `sample_rate`, `channels`, `format: "pcm"` and empty-content `done: true` terminators. Encodings are `f32le` and `pcm16le`. Legacy absent encoding means signed PCM16 little endian.

F31-F2. [`outputUpdateSchema`](../../../packages/protocol/src/messages.ts) wraps values in `output_update`, with `job_id`, `node_id`, `output_name` and optional `disposition` (`append` by default or `replace`) and `done`. Nested chunk `done` also terminates audio. [`AudioOutputNode`](../../../packages/audio-nodes/src/nodes/realtime-audio.ts) passes chunks through and sets `alwaysEmitOutputUpdates`, including when its output is connected to a recorder. [`runner.ts`](../../../packages/execution-core/src/runner.ts) streams these events but deliberately excludes audio updates from retained result messages. Historical result hydration cannot promise full audio replay.

F31-F3. [`workflowUpdates.ts`](../../../web/src/stores/workflowUpdates.ts) publishes audio directly to the playback bus and batches store appends. [`useRealtimeAudioPlayback.ts`](../../../web/src/hooks/browser/useRealtimeAudioPlayback.ts) decodes PCM16/f32le, requests autoplay through the shared audio queue, resumes AudioContext on start, and offers Stop and Restart. Live mode primes at most 40 ms and caps lead to a configurable 20–1000 ms (100 ms default), dropping stale audio. The worklet resamples into the hardware context rate. [`AudioOutBody.tsx`](../../../web/src/components/node_types/synth/AudioOutBody.tsx) selects live mode and defaults to 24000 Hz. Generic [`RealtimeAudioOutput.tsx`](../../../web/src/components/node/output/RealtimeAudioOutput.tsx) defaults to 22000 Hz and mono. Completed streams use replay mode. Both live and generic mounted players initialize `wantsToPlay` to true and auto-enqueue, including retained completed PCM when present. Web autoplay may need a browser gesture. Native has no browser gesture gate, but still needs explicit Start after Stop or device failure.

F31-F4. Native [`PcmStream`](../src/media/PcmStream.cpp) really writes samples to QAudioSink, but its 4 MiB retained buffer eventually refuses every new chunk, even after consumption. It rejects the actual `pcm16le` encoding, rejects valid empty done markers, has no live stale-drop policy, starts an empty stream using default format before metadata arrives, and only accepts hardware float at the source rate. [`RunOutputModel`](../src/run/RunOutputModel.cpp) has one player scoped only by selected run, so separate node/output streams are concatenated. Current Start/Restart controls therefore do not establish sustained monitor parity. These are inspected source findings, not measurements of audible behavior.

## Interfaces and ownership

F31-D1. Keep audio outside media URL resolution. [`MediaResolver`](../src/media/MediaResolver.h), [`MediaPreview.qml`](../qml/MediaPreview.qml), and [`CanvasMedia.qml`](../qml/CanvasMedia.qml) retain completed-file playback, waveform, seeking, download, resolver leases and retained player identity. Live PCM gets a separate stable controller identity. It must never replace an existing file player with a loader merely because another output arrives.

F31-D2. `src/media/PcmStream.h/.cpp` validates sample rate and channels before establishing a QAudioFormat. RunOutputModel encodes session generation, job ID, node ID and output name into the scope string. The live flag selects bounded monitoring versus replay. Decode into a validated frame block before changing controller state. Accept `pcm16le`, provider aliases `pcm16` and `pcm`, absent legacy encoding, and `f32le`. Reject invalid base64, partial frames, invalid channel/rate values, unknown encoding and non-finite samples atomically. Empty done markers succeed without decoding. A valid first block establishes format. Midstream format changes stop with an actionable error until a new stream generation or replacement begins.

F31-D3. `PcmStream` exposes `playing`, `queued`, `queuePosition`, `state`, total source-equivalent `queuedFrames`, `droppedFrames`, `ended`, and a bounded scalar `level`. Its methods are `append(scope, chunk)`, `finish()`, `replace(scope, live)`, `start()`, `stop()`, `restart()`, and `reset(scope, live)`. RunOutputModel validates event scope before invoking finish or replacement. Start before metadata records intent and waits. First valid metadata constructs the sink. Stop resets the hardware queue immediately and suppresses automatic restart. Live Start discards stale pending audio. Replay Start resumes its cursor, while Restart rewinds retained replay. Completed input drains and transitions to Ended. Underrun remains Waiting until more frames arrive, without losing start intent.

F31-D4. Use a bounded frame ring for live audio: 100 ms lead default, 20–1000 ms configurable range, 40 ms maximum prime, whole-frame oldest-drop on overflow. Bound decoded and encoded input before allocation. Retain replay separately up to the existing 4 MiB limit with a clear truncation notice. Live playback must continue beyond that amount. Never retain each payload again in output entries or collection models. Meter storage and telemetry also have fixed caps. Drain handles short/zero/error writes without replaying accepted bytes and preserves frame ordering.

F31-D5. Hardware is isolated behind `PcmSink`: `preferredFormat()`, `supports(format)`, `start(format)`, `capacityBytes()`, `bufferedBytes()`, `write(bytes)`, `drained()`, `failed()` and `stop()`. Production implementation owns QAudioSink on its QObject thread. Prefer exact source format when supported. If unavailable, select a supported device format and explicitly convert source rate, interleaved channels and sample representation using bounded conversion state. Never merely relabel source samples with the device rate. Unsupported channel mappings show a readable failure. Stop, replacement and reset clear converter history. Device removal fails visibly and requires Start to reopen a current device. No new threads are required for the initial implementation. Use context-bound connections and Qt ownership under C++20.

F31-D6. `RunOutputModel` owns controllers keyed by complete PcmScope and exposes `QObject *pcmFor(nodeId, outputName)` plus stream keys in output entries. Session generation changes on account/server/workflow reset. Validate job identity and sequence before audio routing. Route every accepted append once, and process `replace` as replacement rather than another append. Honor outer and inner done. Reject late frames after terminal failure/cancellation, reset, or stream end. Success drains buffered frames. Switching selected runs stops and dequeues old monitoring. Historical run selection clears PCM controllers and does not autoplay. Generic and live autoplay applies to current accepted PCM data. Historical results without PCM cannot manufacture a replay. Reset destroys all session audio data. The host must call reset on account/server changes before new events can arrive.

F31-D7. `OutputCollectionModel` stays a presentation model with stable collection keys. It stores controller keys and compact status, never audio bytes. `qml/RichOutput.qml` binds the matching controller and supplies Start/Stop/Restart, queue/wait/end/error text and a bounded live level view composed with shared Ui primitives. An application-owned, injectable FIFO PCM audio queue shared across RunOutputModels and EditorWindows allows one audible PCM controller at a time. Starting another player queues it without stopping the current player. Both generic and live player mount request autoplay when PCM exists. Queue position is one-based and excludes the active player. Controller identity remains stable across output updates, so those updates do not repeatedly enqueue it. An explicit Stop remains authoritative until Start or Restart.

## Queue and lifecycle contract

F31-D8. Queue entries observe controllers with `QPointer` and context-bound connections. Destroying an active controller stops its sink and promotes the next surviving entry. Destroying a waiting controller removes only its entry. The application owns the default queue, while tests inject a queue shared by multiple models. Extend the queue service under `src/media/`, and inject it through RunOutputModel without creating a queue per model. Existing completed-file QMediaPlayer behavior remains separate. No evidence here establishes that file playback participates in the web PCM queue.

[`AudioQueueStore.ts`](../../../web/src/stores/AudioQueueStore.ts) is the queue authority. Enqueue starts immediately only when idle. Otherwise it removes an existing waiting item with that identity and appends it at the tail. Dequeue of the active item promotes the FIFO head, with the caller responsible for stopping its sink first. Dequeue of a waiting item removes only that item. `finishCurrent` promotes the head without calling onStop. `stopAll` stops the active callback and clears all waiting items without promotion. Native start requests should be idempotent for an already active controller, avoiding a second entry for that same controller.

F31-D9. The hook's Stop sets autoplay intent false, stops scheduled sound, then dequeues. Restart performs Stop, clears its scheduled-chunk identity set and visualizer, and requests Start after 50 ms. Consequently a waiting second output can become active before the restarted first output joins the tail. Native must preserve that ordering. Use the context-bound single-shot timer, canceled by destruction, reset or later Stop, so a delayed Restart cannot resurrect stale sound. Unmount releases queue membership and sound ownership. Scope-wide account reset uses stopAll before controller destruction and never promotes an old waiting item during teardown.

F31-D10. The inspected web hook does **not** call `finishCurrent`, inspect chunk done, or release its queue slot when individual AudioBufferSourceNodes end. Its onended only disconnects a source. The store defines finish promotion, but automatic end promotion is absent from this hook. Native explicit done/drain handling in D3 is a proposed correction: release the slot after the final hardware-buffered frame drains, then promote the FIFO head. A live underrun without done must retain the slot and wait. Native device/decode fatal errors stop and dequeue to avoid blocking later outputs, then require explicit Start or Restart to retry. Web catches several start/stop errors without exposing a corresponding error state, so this error recovery is also a native behavior decision rather than a claim of existing web parity. The parent approved both as deliberate native corrections to the unused web finishCurrent path.

## Integration and implementation order

F31-A1. This work owns `src/media/PcmStream.h/.cpp`, with sink, converter and application queue kept in those existing files, PCM tests, and the PCM section of `qml/RichOutput.qml`. This work also owns `src/run/RunOutputModel.h`, `src/run/RunOutputModel.cpp`, `src/run/OutputCollectionModel.h` and `src/run/OutputCollectionModel.cpp` for scoped audio routing, controller lookup and compact controller references. Changes outside those audio paths require coordination with the parent. Parent owns CMake registration. No backend, npm, or web source changes are required.

F31-A2. Dynamic-card owner supplies a stable `nodeId/outputName` to `pcmFor` and renders the same controller for an Audio Out card. Request host wiring to reset audio before account/server/workflow transitions and cancel immediately on run cancellation. Do not edit EditorScene or EditorWindow in this wave. Preserve existing media presenter retention and completed waveform paths.

F31-A3. Validate decoding and end handling, then the ring, converter and sink, then scoped routing, FIFO arbitration and controls. Run focused fake-stream checks, native host tests, related media retention checks and sanitizer gates. Report actual-device coverage separately.

## Acceptance and deliberate mutations

| Case | Fake-stream acceptance | Mutation that must fail |
| --- | --- | --- |
| Actual wire forms | Feed 24 kHz mono f32le and PCM16LE stereo `output_update` messages through RunOutputModel into a recording sink. Assert exact frame order and finite amplitudes. | Reject `pcm16le`, swap endian order, or route only file refs. |
| Metadata timing | Start before first block, then send 48 kHz stereo metadata. Assert sink configuration uses that format once. | Open default 22000 Hz sink eagerly. |
| Terminators | Empty nested done and outer done drain once, show Ended, reject later frames. | Decode empty done as malformed or keep playing Waiting forever. |
| Sustained live input | Feed more than 4 MiB while consuming, then a prolonged producer burst. Assert newest frames reach the sink, ring stays within cap, and dropped count advances by whole frames. | Keep consumed replay bytes in the live cap or drop newest frames. |
| Negotiation | Fake hardware accepts only 48 kHz int16 stereo. Feed 24 kHz float mono tone and assert doubled frame duration mapping, duplicate channels, bounded sample conversion and no discontinuity across chunk boundaries. | Relabel 24 kHz bytes as 48 kHz or reset interpolation at each block. |
| Delivery | Force partial, zero and failed writes and underruns. Assert no duplicated/reordered bytes, bounded retry and immediate stop on error. | Consume requested rather than written bytes. |
| Identity | Interleave two nodes and output names, duplicate job_seq, stale job/account generation and replacement snapshots. Assert stream separation, exactly-once routing and reset on replacement. | Scope only by job or append replacement snapshot. |
| Cancellation | Cancel or switch account during queued playback and conversion. Assert sink stopped and buffers cleared before any later callback. Success instead drains. | Leave sink active or permit stale events to restart it. |
| Cross-window ownership | Two RunOutputModels share one queue. Start their controllers and assert only the first sink receives frames. Destroy the active controller and assert the next surviving controller starts once. Destroy a waiting model and assert it is never invoked. | Create one queue per model, dereference a destroyed QObject, or promote during whole-session teardown. |
| FIFO and restart | Mount A then B with PCM. Assert A sends frames to its sink and B shows position 1. Stop A promotes B. Restart A while B waits promotes B first and queues A at the tail. Stop a waiting item removes only it. Reset stops all without promotion. | Preempt A on B Start, autoplay only live players, or permit delayed restart after reset. |
| End and errors | Done drains hardware then promotes next once. Underrun without done retains the current slot. A fatal device error stops/dequeues and exposes retry state. | Finish at input receipt before device drain, promote on temporary starvation, or block queue forever after error. |
| Controls and retention | Invoke accessible Start/Stop/Restart on the matching controller. Repeated output updates preserve controller and existing file player identities. Stop prevents subsequent auto-start. | Bind every PCM row to one shared run player or recreate delegates per chunk. |
| Live UI updates | Hold native Stop pressed while an existing output updates or a sibling first arrives. Assert control identity, focus, release action and matching FIFO promotion survive. | Replace the rich item model with a wholesale QVariantList Repeater reset. |
| History pressure | Keep an active and queued monitor through count and byte truncation. Assert controls remain represented, persistent indexes survive and preview bounds hold. | Evict PCM rows with removeFirst or reset all delegates for a middle history removal. |
| Native ownership | Invoke pcmFor through a protected native bridge root, release JavaScript handles and collect garbage. Query rich roles during controller destruction and retain file-media indexes. | Leave the reused member controller parentless or delete controllers before removing their public roles. |
| Bounded failures | Oversized payload, malformed base64, partial frames, NaN, format changes and device removal each expose readable state and preserve previous valid buffer atomically. | Allocate before size check or partially commit invalid samples. |

Fake sinks prove routing and sample delivery without audio hardware. A separate actual-device check must confirm a generated tone can be heard, Stop silences it, and playback continues during sustained input. Report hardware coverage separately from offscreen checks. Live level visualization is not proof of audible playback.

## Validation and lifecycle contracts

F31-A4. [`PcmStreamTest.cpp`](../tests/media/PcmStreamTest.cpp) and [`RunOutputModelTests.cpp`](../tests/run/RunOutputModelTests.cpp) reproduce the baseline failures: rejected pcm16le, rejected empty done, consumed lifetime storage exhaustion and missing per-output controllers. Sustained buffering selects explicit live mode. Replay retains bounded storage.

F31-A5. `setLiveNodes(const QSet<QString> &)` accepts a complete monitor-node projection before ingest. The host identifies `nodetool.audio.realtime.AudioOutput`. Existing account, workflow-open and local-file transitions already call `runOutput_.reset()`. Reset atomically removes this model's audio controllers and promotes only surviving other-model entries. It retains the projected live-node configuration until the next host projection. Mode remains stable for an active stream generation.

F31-A6. Existing `node_editor_run_tests` covers the original regressions and stable rich-row identity. Existing `node_editor_pcm_tests` adds injected-device conversion, short writes, sustained live bounds, FIFO, delayed Restart invalidation, done-drain promotion, fatal error release, cross-model arbitration and destruction. No new CMake sources, resources or test targets are needed.

F31-A7. Live lead accounting includes the source ring, interpolation state, unsent converted bytes and hardware-buffered bytes. Each accepted chunk trims oldest unscheduled source frames against the remaining whole-frame budget. The fake sink exercises 24-to-48 kHz conversion, partial writes, hardware consumption and producer bursts while checking the combined lead. Audio Out's metadata-free default is 24000 Hz, while generic PCM remains 22000 Hz.

F31-A8. Replay preserves unsent conversion state across Stop and rewinds an incomplete accepted output-frame prefix after hardware reset. The pump fills available device capacity within a byte and iteration budget, including high source rates. Every replacement retires the prior PCM generation. Explicit live Start discards stale frames. Failure and cancellation clear selected-run PCM atomically, while success drains. A changed device format with unsent converted replay requires Restart rather than reinterpreting bytes.

F31-A9. [`realtime-tts.ts`](../../../packages/elevenlabs-nodes/src/nodes/realtime-tts.ts) derives encoding from the first output-format segment. Its `pcm_44100` output therefore uses the additional PCM16LE alias `pcm`, now accepted. Compressed realtime MP3/Opus remains an F31 gap, including the provider's default MP3 format. Native reports unsupported encoding instead of interpreting compressed bytes as PCM samples. This gap is not an approved exclusion from full parity.

F31-A10. [`RichOutputHostTest.cpp`](../tests/ui/RichOutputHostTest.cpp) exercises actual mouse Start/Stop/Restart and holds Stop pressed during an existing-output update or first sibling arrival. The constant richEntries model reuses OutputCollectionModel with stable per-kind/node/output/event keys and a richEntry role. Only the rich-output Repeater uses that model. Media collections and file-player ownership remain separate.

F31-A11. Scoped cleanup removes rich model roles before deleting child controllers. A destruction observer checks the public roles during that phase while retaining a completed-file collection index. The first reused PCM controller is parented to RunOutputModel, matching later controllers and existing member-model ownership. A host check invokes pcmFor through the QML JavaScript bridge, releases its handles and collects garbage to verify native lifetime.

F31-A12. History eviction retains active and queued PCM control rows. Diagnostics are evicted before output previews. If pinned mixed-media previews alone exceed the byte bound, preview payloads are compacted while the PCM controls remain. The display count and byte bounds still apply. OutputCollectionModel preserves indexes across order-preserving range removals and inserts, and resets for scope changes, actual reorders or ambiguous keys. Tests cover sustained log and byte pressure, mixed-preview pressure, retained media indexes and large range updates.

F31-R1. RunOutputModel retains at most 64 node/output controllers, including stopped and completed streams, until its audio scope resets. A new stream at that capacity has no controller. The current UI uses the general unavailable-stream message and does not explain capacity or how to clear it. Capacity feedback and retention refinement remain F31 limits.
