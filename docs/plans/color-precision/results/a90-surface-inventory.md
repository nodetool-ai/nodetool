## Precision and loading findings

- F1: `context.ts` derives `f16Storage` from enabled `shader-f16`. Executor checks that capability for variants. No inspected module enables that requirement and `node.ts` requests no features. RGBA16F texture storage itself does not need shader-f16. The capability name/comment should not drive the S0 proof.
- F2: Compute layout storage formats, resolved WGSL declarations, recipe intermediates, scratch allocations, uploads and readback all matter. The enumeration below records every matching shader module in this checkout instead of extrapolating the review's count on main.
- F3: Preserve the lazy `gpu/node` → dynamic `webgpu` import. Pure catalogs, document schemas and ordinary agent tools must remain loadable without initializing Dawn. Node rendering currently reports adapter setup guidance when acquisition fails. Do not retire an agent CPU path before qualifying its replacement.
- F4: CPU source rasterization, decoding, encoding, saved-layer IO and editor mutations have distinct purposes. They cannot all be deleted when switching a compositor format. Color-space labels are not proof of transfer conversion. S0 preserves current arithmetic.
