# Plan 2: Native timeline precision and export

Deferred companion to [Plan 1](high-precision-media-processing.md). Activate this work when native integration is scheduled. P1 can proceed independently, sharing numerical vectors with native code. Working precision is a renderer choice, with no saved profile, document copy flow or new precision setting.

**Scope:** existing supported 8-bit SDR decoding, FP16 processing and ordinary 8-bit delivery. Reuse compatible frame/alpha contracts where useful. Do not make native integration a dependency of browser/server work or let native monitor settings determine web UI scope.

N1–N3 preserve existing effect meanings and adopt P1's A97/A98 color declarations and boundary checks. N4 separately adopts [linear-light SDR](high-precision-media-processing.md#s6-linear-light-sdr-after-fp16-delivery) for documents at [working color space version](high-precision-media-processing.md#working-color-space-version) 2. Neither P1's nor native FP16 delivery waits for N4. The native timeline ships as a separate download from Electron, so web and native versions can differ for a long time. A108 is the one task here that cannot wait for native integration, because it must be released before P1's A102.

**Implementation direction:** C++ with the existing Qt/QML UI. Qt RHI remains the baseline. Evaluate Dawn only as a C++ rendering alternative with demonstrated shader-reuse and operational benefits. Rust, language-neutral host abstractions and a UI rewrite are outside this plan.

## N2: Presentation and native export

Owner roles: native renderer and export maintainers. Preview and export must use the same compositor evaluation. Only the final output conversion differs.

- [x] **A32: Separate working pixels from window presentation.** Keep internal working resources FP16. The QQuickRhiItem presentation target may remain RGBA8 with P1's final SDR conversion/dither. Do not require a float outer Qt scene target for export. Keep numerical working capture undithered. Test paused redraw stability and GL readback orientation.
- [x] **A45.2: Qualify existing native resolution controls for FP16.** Reuse playback/paused Full/Half/Quarter/Eighth controls, project-space transforms and forced full-resolution capture. Preserve existing full-canvas exceptions for group effects/backdrop adjustments across motion-blur samples. Measure actual canvas/scratch allocations and extend geometry, mask/outset and capture-isolation checks for float resources. Do not add another selector or make optimizing those conservative exceptions a release prerequisite.
- [x] **A84.1: Make internal canvas capture format-aware.** PreviewCompositor captures m_canvas before its final item blit. Replace its hardcoded RGBA8888-premultiplied interpretation and OffscreenFrames' byte conversion with a typed working capture or an explicit final GPU delivery pass. Preserve dimensions, row layout, orientation and completion lifetime. The outer RGBA8 scene target is not the export source. Test exact frame capture and undithered numerical readback.
- [x] **A84.2: Connect ExportEngine to the qualified delivery conversion.** Keep existing codecs, layouts and opaque capture background for video/PNG. For the straight-RGBA conversion seam, unpremultiply in float before quantization and define alpha-zero handling. Convert once and avoid repeated display/delivery dithering. Explicit-size export breaks this today: [`fitFrame`](https://github.com/nodetool-ai/nodetool/blob/33963a5d7111bda52f116392d1b7c34eab7e3430/native/timeline/src/export/ExportEngine.cpp#L358) resamples the captured RGBA8 image, then [`sws_scale`](https://github.com/nodetool-ai/nodetool/blob/33963a5d7111bda52f116392d1b7c34eab7e3430/native/timeline/src/export/ExportEngine.cpp#L371) converts those bytes to limited-range YUV420P. [Video from an odd canvas](https://github.com/nodetool-ai/nodetool/blob/33963a5d7111bda52f116392d1b7c34eab7e3430/native/timeline/src/export/ExportEngine.cpp#L340) is also resampled in bytes, to the even encoded size. Resample on the float frame before quantization, for video and PNG, then apply P1's A88 dither. Preserve fit, fill and black-bar behavior. Accept with explicit-size exports in both modes, up and down, for video and PNG, plus an odd-canvas video: decode the output and compare it against the same frame resampled in float, within declared tolerances. Retain bounded memory, cancellation and streaming. No new float encoder ABI or transparent-export feature is required.

  `export_precision` now compares full decoded frames with an independently resampled float canvas, with separate pre-encode and codec bounds. See the [Vulkan/lavapipe results](results/n2-native-export.md#a842-decoded-spatial-acceptance).
- [x] **A84.3: Verify native frame and still capture paths.** Exercise video output and existing PNG/ZIP delivery. Make each quantization point explicit. Check low-alpha edges over the existing capture background, cancellation, cleanup and pixel layout. Test alpha-zero/straight-alpha conversion separately at the internal helper. Preserve existing output alpha behavior.
- [x] **A41.3: Qualify the existing 8-bit native delivery profile.** Decode the actual output and inspect pixels, format and color tags. Compare codec error separately from working precision. Do not claim higher-depth delivery merely because source processing is float. Follow the [A101 owner decision](high-precision-media-processing.md#s6-linear-light-sdr-after-fp16-delivery): pass through delivered values with today's BT.709 tag (O1), accepting its transfer mismatch to preserve source appearance.
- [x] **A43.3: Compare native preview and export before encoding.** Render the same original-source frame, background, parameters and deterministic seeds. Compare undithered working pixels from preview and offscreen evaluation. Extend existing capture-isolation checks so zoom, alpha/grid display and resolution preferences cannot enter exported pixels. Apply separate tolerances for final dithering and encoded output.

Primary modules: [OffscreenFrames.cpp](https://github.com/nodetool-ai/nodetool/blob/33963a5d7111bda52f116392d1b7c34eab7e3430/native/timeline/src/export/OffscreenFrames.cpp), [ExportEngine.cpp](https://github.com/nodetool-ai/nodetool/blob/33963a5d7111bda52f116392d1b7c34eab7e3430/native/timeline/src/export/ExportEngine.cpp), [capture code](https://github.com/nodetool-ai/nodetool/blob/33963a5d7111bda52f116392d1b7c34eab7e3430/native/timeline/src/main.cpp).

**Current qualification:** A32 and A45.2 are met on the tested backends. A84.2's decoded spatial-resize comparison passes on Vulkan/lavapipe. Its new assertions await other backend runs. See the [clause audit](results/plan-status-audit.md).

**Exit gate:** native export preserves the precision improvement through the last intentional conversion, including explicit-size exports. Window formatting cannot alter export evaluation, and reduced preview resolution cannot reduce export quality.

## N3: Qualify the supported release

Owner role: native release maintainer. Qualify the concrete Windows route first, then other backends independently. Do not claim untested support.

- [x] **A34: Run numerical checks on supported backends.** Reuse the native branch's Metal, Vulkan/lavapipe and D3D11/WARP CI. It has no explicit OpenGL precision job, and OpenGL may still be a live route on Linux. [ExportCli](https://github.com/nodetool-ai/nodetool/blob/33963a5d7111bda52f116392d1b7c34eab7e3430/native/timeline/src/export/ExportCli.cpp#L58) and [FrameServerCli](https://github.com/nodetool-ai/nodetool/blob/33963a5d7111bda52f116392d1b7c34eab7e3430/native/timeline/src/export/FrameServerCli.cpp#L177) pass `false` to `selectGraphicsApi`, so [HwWindow](https://github.com/nodetool-ai/nodetool/blob/33963a5d7111bda52f116392d1b7c34eab7e3430/native/timeline/src/preview/hw/HwWindow.cpp#L65) does not force Vulkan. CI selects its backend through `QSG_RHI_BACKEND`. The [README](https://github.com/nodetool-ai/nodetool/blob/33963a5d7111bda52f116392d1b7c34eab7e3430/native/timeline/README.md#L127) and a code comment say that Qt's Linux default is OpenGL, and no check measures this, so confirm it. Run both routes without the variable, with `QSG_INFO=1` and `qt.rhi.general` logging, and record the backend. Then qualify that backend, including orientation and render checks, or force a backend in those entry points. Check FP16 targets, filtering, low alpha and row orientation. A backend is not qualified by another backend's pass. [Linux measurements and CI checks](results/n3-native-backends.md) qualify the tested OpenGL and Vulkan routes. Metal and D3D11/WARP also pass the [combined CI checks](results/n3-native-backends.md#ci-confirmation).
- [ ] **A49.2: Measure the Windows hardware route.** Record the actual adapter and run P1's playback, seek and memory gates, including decode cache and export. Include a constrained supported target before broad performance claims. Software CI does not establish hardware speed or decode interop. No new P010/platform interop work is required.
- [ ] **A50.2: Enable FP16 on qualified native routes.** Use internal renderer configuration. Test existing documents without migration, unavailable capabilities, full-resolution export, repeated sessions and cleanup. Qualify platform software adapters such as WARP with the same native shaders before relying on them. Do not introduce a separate CPU effect renderer, require lavapipe on Windows or add a document-level device gate.

**Exit gate:** a named native backend meets numerical, export and resource criteria. Diagnostics identify actual processing. Unsupported-device behavior follows the explicit route policy without changing document access incidentally.
